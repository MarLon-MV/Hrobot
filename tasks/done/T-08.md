# T-08: Namespace por robot (`/r2`, configurable) y script para cambiar de robot

- **Rama Git:** `feat/autonomous-exploration`
- **Depende de:** T-06, T-07
- **Commit:** `feat(bringup): ...`

## Contexto
El Create 3 de este robot vive en el namespace `/r2` (robot 2): publica `/r2/odom`, `/r2/tf`, `/r2/tf_static` y escucha `/r2/cmd_vel`. Los launch de T-06 asumen que no hay namespace y no funcionarían. Se quiere que **todo el stack lleve el nombre del robot** y que se pueda cambiar para otros robots con otro nombre.

## Objetivo
1. **Argumento `robot_namespace`** en `master_explore`, `hardware_base` y `navigation` (los tres lo aceptan y se lo pasan entre sí). Por defecto: variable de entorno `CREATE3_ROBOT_NAMESPACE` si existe; si no, `r2`. Vacío = sin namespace (compatible con simulación).
2. **Todos los nodos bajo el namespace** (`PushRosNamespace`): robot_state_publisher, driver LD19, slam_toolbox, Nav2 (controller, planner, smoother, behavior, bt_navigator, lifecycle managers, map_saver), explorer_node, map_manager_node y rviz2. Resultado: `/r2/scan`, `/r2/map`, `/r2/frontiers`, `/r2/explore_map`, `/r2/navigate_to_pose`, `/r2/save_exploration_map`, etc.
3. **TF por namespace:** remapeos `('/tf','tf')` y `('/tf_static','tf_static')` en todos los nodos que usan TF (patrón de `nav2_bringup`), de modo que lean y publiquen en `/r2/tf` y `/r2/tf_static`, donde está el TF del Create 3. Los `frame_id` NO llevan prefijo (`base_link`, `odom`, `map`, `laser_frame`).
4. **Parámetros bajo namespace:** los YAML con clave de nodo (`controller_server:`, `slam_toolbox:`, `explorer_node:`, ...) no cargan en nodos con namespace. Reescribirlos al arrancar con `nav2_common.launch.RewrittenYaml(root_key=<namespace>)` (o equivalente), y que con namespace vacío no cambien.
5. **Nombres relativos:** cambiar los topics/servicios absolutos por relativos para que respeten el namespace: `/scan`→`scan`, `/odom`→`odom`, `/map`→`map`, `/frontiers`→`frontiers`, `/map_saver/save_map`→`map_saver/save_map`, `/slam_toolbox/serialize_map`→`slam_toolbox/serialize_map`, en `nav2_params.yaml`, `slam_params.yaml`, `explorer_params.yaml`, y los defaults en `explorer_node.cpp` y `map_manager_node.cpp`. `cmd_vel` debe resolverse a `/r2/cmd_vel`.
6. **RViz:** `exploration.rviz` con marcador `<robot_namespace>` en los topics y `ReplaceString` al lanzar (patrón de `nav2_bringup`), con TF remapeado.
7. **Script `scripts/set_robot.sh <nombre>`:** valida el nombre (`^[a-z][a-z0-9_]{0,31}$`), escribe `CREATE3_ROBOT_NAMESPACE=<nombre>` en `~/.config/create3_bot/robot.env` y añade (una sola vez, idempotente) una línea a `~/.bashrc` que lo cargue. Opciones: `--show` (muestra el nombre actual), `--check` (comprueba con `ros2 topic list` que existen `/<nombre>/odom` y `/<nombre>/cmd_vel`), `--unset`. Informar de que el namespace del propio Create 3 se configura en su interfaz web y que el script no lo cambia.
8. **Documentación:** actualizar `src/README.md` y los README de explorer y bringup (comandos con `/r2/explore_map`, `/r2/save_exploration_map`, `robot_namespace:=`, `scripts/set_robot.sh`) y `scripts/setup_pi.sh` (mensaje final con el namespace).
